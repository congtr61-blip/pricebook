## v4.0（账号管理主线已实现；启用前需完成下方配置）

### 账号管理与密码安全
- [x] 管理员创建商户账号，填写邮箱、商户名称、电话和标签
- [x] 创建账号后提供每账号独立的一次性随机临时密码；首次登录后必须修改密码
- [x] 用户可在个人账号页面主动修改密码
- [x] 未完成首次改密时，服务端页面、业务 API 和数据库 RLS 均限制业务访问
- [x] 管理员可为商户重置随机临时密码，并重新要求首次登录改密
- [x] 商户列表显示账号状态：“待首次改密”或“正常”
- [x] 创建或重置成功后临时密码只显示一次，并提供复制操作

### 密码安全决策
- 使用每账号独立的随机临时密码，不采用多个账号共用 `123456` 的方式。
- 系统只保存临时密码的 SHA-256 摘要以阻止用户把临时密码原样设为新密码；成功改密后立即清除摘要，不保存明文密码。
- 使用 `must_change_password` 标记强制改密状态，由 Supabase Auth 负责密码验证和更新。

### 上线前配置与验证
1. 在 Supabase SQL Editor 执行 v4 迁移。
2. 本地 `.env.local` 和 Vercel 环境变量中配置仅服务端可访问的 Supabase Service Role Key。
3. 使用普通商户账号验证不能访问业务页面、API 或直接读取业务表，直到完成改密。
4. 使用管理员账号验证创建商户、一次性显示临时密码、首次改密、主动改密和密码重置流程。

## 数据库迁移

请在 Supabase SQL Editor 中按需执行以下迁移文件：

- `supabase/migrations/20260922_v2_orders.sql`
- `supabase/migrations/20260922_v2_admin_order_and_content.sql`
- `supabase/migrations/20260922_fix_messages.sql`
- `supabase/migrations/20260922_fix_order_inventory.sql`
- `supabase/migrations/20260923_v3_profile_and_order_fields.sql`
- `supabase/migrations/20260927_v4_account_security.sql`

请按以上顺序执行。若 v4 迁移提示缺少 `business_hours`、`announcements` 或 `messages`，先单独执行 `20260922_v2_admin_order_and_content.sql`，再重新执行 v4 迁移。

管理员创建和重置账号需要配置服务端 Supabase Service Role Key：本地写入 `.env.local`，部署时添加到 Vercel 项目环境变量。变量名为 `SUPABASE_SERVICE_ROLE_KEY`，不得使用 `NEXT_PUBLIC_` 前缀或提交密钥值。
